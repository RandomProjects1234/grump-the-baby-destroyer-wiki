FAQ / Troubleshooting

My keyboard/mouse isn't doing anything

The game uses browser pointer lock for mouse look. Click the game canvas once to lock your cursor to it. If you've clicked away (another browser tab, a different window, pressed Esc), you'll need to click the canvas again. Losing pointer lock during solo play automatically pauses the game.

The game seems stuck / a new version isn't showing

This is a static, no-build site served straight from GitHub Pages, so a stale service worker or browser cache is the most common cause of "it looks old." Try a hard refresh (Ctrl/Cmd+Shift+R), or open the game in a private/incognito window to confirm whether it's a caching issue.

Co-op room codes aren't working

Room codes are five letters, generated by PeerJS when the host opens a room. A few things to check:

  • The host's tab must stay open the whole time — the host machine is running the actual simulation, not a server somewhere else.
  • Codes are case-insensitive but must otherwise match exactly; the join field automatically uppercases and strips anything that isn't a letter or digit.
  • PeerJS relies on WebRTC, which can be blocked by some corporate/school networks or aggressive browser privacy settings — if joining consistently fails, try a different network.

Why do my searches keep coming up empty?

This is by design and gets more noticeable the longer a run goes: the odds of a container actually holding something drop every night, hitting their leanest around night 8 and staying there. See Loot Tables for the exact percentages per container and per night.

Grump turned before day 4 — is that a bug?

No. Pushing his resentment to 100 through rude answers, ignoring him, or leaving messes uncleaned brings his turn forward; being polite never delays it past day 4. Day 4 is a hard ceiling, not a fixed trigger point — see Grump for the full resentment math.

I can't find Bob on the map

That's intentional — Bob is never shown on the map, at any time, in any circumstance. See The Map.

I lost the game / it crashed — is progress saved?

There is no save system between runs; each run plays start to finish in one sitting. Your settings (sensitivity, volume, field of view, name) persist locally in your browser between sessions, but a run itself does not resume after closing the tab.

The game runs slowly

Open Settings and lower Quality (Low/Medium/High). The renderer only actively shades a handful of point lights at once regardless of setting (there are roughly 75 light fixtures across the school, but you can typically only see one or two rooms' worth at a time), so quality mostly affects other rendering costs.

Jerry keeps chasing me down

Hide. Getting into any hiding spot before he reaches you makes him give up on the spot ("I know you're in there! Next time, champ!"), and he's capped at 2 attempts a day regardless. He also never comes in the last 110 seconds of the day. See Jerry.

I searched the same locker twice and got nothing the second time — is that normal?

Yes. Every repeat search of the same container on the same day has a shrinking chance of finding anything at all — 45% on the second search, 20% on the third, and so on. See Searching for the exact numbers, and note the container's search count resets fresh every morning.

When does the Big Boys Club scene happen?

Once per run, on day 2 or 3 (chosen randomly at the start), always before Grump turns on day 4. It's scripted and unavoidable once its conditions are met — you can't skip it, fail it, or trigger it a second time. See The Big Boys Club.

Who made this?

Grump the Baby Destroyer is an original game; see the game's source repository for authorship and history. This wiki is an unofficial fan reference, built from that source code — see the Changelog for what's changed recently.
